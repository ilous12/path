# MARS 제품 요구사항 정의서

- 문서 버전: v1.0
- 작성일: 2026-09-21
- 상태: 현업 검토용
- 제품 포지셔닝: 온라인 통신 정책 의사결정 지원 도구
- 적용 순서: AIR 실증 → TDS·MVNO 통합

## 1. 제품 목적

MARS는 시장 변화와 자사 실적을 함께 분석하고, 정책 후보의 예상 효과를 비교해 마케터의 의사결정을 지원한다. 데이터를 수집·정제하는 업무부터 변화 감지, 정책 검토, 실험 등록, 결과 평가까지 하나의 흐름으로 연결한다.

1차는 “무엇이 달라졌고 우리 사업은 어떤 상황인가?”에 답한다. 2차는 “앞으로 어떻게 될 수 있으며 어떤 정책을 선택할 것인가?”에 답한다. 초기 적용 대상은 AIR이며, 마케터 피드백을 반영해 공통 기능을 정리한 뒤 TDS·MVNO로 확산한다.

## 2. 사용자와 업무 재정의

주요 사용자는 AIR·TDS·MVNO 정책 운영 담당자와 팀장이다. 요건 협의에는 관련 팀장 4명이 참여한다. MNO는 주요 시장 비교 대상이며, 별도 내부 운영 조직으로 가정하지 않는다.

| 기존 업무 | MARS에서의 업무 |
| --- | --- |
| 모요·경쟁사 사이트에서 요금과 혜택을 개별 확인 | 출처와 관측 시점을 갖춘 시장 이벤트 통합 확인 |
| 엑셀로 상품 조건·가격 차이와 실적을 비교 | 동일 조건의 상품군 및 기간·채널별 지표 비교 |
| 경험에 기반해 정책 변경 필요성 판단 | 변화·실적·제약을 근거로 대응 필요 / 관망 / 대응 불필요 검토 |
| 정책별 효과를 수작업으로 가정 | 우선순위와 실행 조건에 따른 정책 후보 시뮬레이션 |
| 정책 시행 후 별도 자료로 성과 확인 | 등록한 가정·예측·관측값을 연결해 결과 평가 |

최종 정책 선택과 실제 업무 반영은 담당자가 결정한다. MARS의 ‘실험 등록·적용’은 시뮬레이션과 타임라인 반영을 의미하며, 통신사의 실제 요금·혜택을 자동 변경하지 않는다.

## 3. 단계별 범위와 일정

| 단계 | 목표 | 주요 산출물 |
| --- | --- | --- |
| 요건 협의 1~3주차 | 수집·조회·분석·실행 요구와 실제 판단 기준 정리 | 업무 흐름, 데이터 목록, 화면 구성, 평가 항목 |
| 요건 확정 4주차 | 구현 기능·데이터·평가 기준·일정 합의 | 확정 요구사항과 단계별 계획 |
| AIR 실증: 2026년 10월 1주차까지 목표 | 기존 업무와 병행 사용하며 현황 분석·정책 실험의 유용성 검증 | AIR 실증 결과, 마케터 피드백, 개선 우선순위 |
| 통합: 이후 약 1개월 | TDS·MVNO의 데이터·채널·판단 기준을 공통 구조에 연결 | 통합 워크플로우, 조직별 설정 |
| 2026년 11월 운영 흐름 정착 목표 | 데이터 확인부터 제안·실험·평가까지 반복 운영 | 운영 지표, 오류 관리, 개선 주기 |

일정은 목표이며, 데이터 제공 범위·담당 인력·연동 가능 시점을 확인한 뒤 확정한다. 원가·마진·실제 정책 시행 이력 확보 여부는 2차 분석의 선행 조건이다.

## 4. 핵심 사용자 흐름

**시장·실적 확인 → 이벤트·변곡점 분석 → 중점 지표 우선순위 선택 → 정책 제안 → 시뮬레이션 비교 → 사용자 선택 → 실험 등록 → 타임라인 확인 → 결과 평가**

정책 실험의 진입 흐름은 다음과 같다.

1. 타임라인의 `+`에서 등록 유형을 선택한다.
2. `정책 실험`을 선택하면 `AI 자동 제안 / 사용자 선택`을 제공한다.
3. AI 자동 제안은 회선 성장·이탈 방어·수익성의 1·2·3순위를 선택한다. 같은 지표를 중복 지정할 수 없다.
4. 진입 화면의 기간·사업자·채널·선택 이벤트·변곡점을 산출 기준으로 사용한다.
5. ‘어떤 정책을 검토할까요?’에서 현행 유지·단기 검증·장기 검증을 비교한다.
6. 사용자가 기간·변경 요건·예측 알고리즘·비용 가정을 확인한 후 실험을 등록한다.

## 5. 화면별 요구사항

### 5.1 시장.정책 현황

- AIR를 기본으로 TDS·MVNO의 현황을 전환한다.
- 상단에서 조회 기간을 선택한다. 월간·일간·시간 구간 등 집계 단위는 원천 데이터 해상도에 맞춰 제공한다.
- 시장·실적 타임라인을 중심 콘텐츠로 배치한다. 부가 설명과 요약은 작게 표시한다.
- 타임라인의 기본 선형 지표는 회선·해지이다. 매출·순익은 지점 툴팁에서 함께 확인한다.
- 경쟁사·기타, 변곡점, 자사 이벤트, 실험을 구분해 어노테이션으로 표시한다.
- 하단 기간 드래그바의 양 끝으로 범위를 조절하고 가운데로 기간을 이동한다. 차트 본문 좌우 드래그로 기간을 이동하며, Ctrl + 휠로 확대·축소한다. 조회 기간은 데이터 범위를 넘지 않는다. 일반 휠은 페이지 스크롤로 동작한다.
- 기간 선택 버튼으로 조회 기간을 바꾸면 콘텐츠 영역에 스켈레톤을 표시한다. 휠·드래그바·본문 드래그 조작은 스켈레톤 없이 현재 화면을 유지하며 갱신한다. 제목과 조회 조건은 유지한다.
- 회선 성장·이탈 방어·수익성의 공통 중점 지표는 현황 화면에 배치하지 않고 설정에서 관리한다.

### 5.2 이벤트·변곡점·실험 어노테이션

- 호버 시 요약 말풍선과 영향 기간 영역을 표시한다. 말풍선은 선형 차트 렌더링 영역 위에 배치한다.
- 클릭 시 해당 항목의 상세 분석으로 이동한다.
- 중첩 항목은 건수 배지로 묶고, 영향 영역은 가장 이른 시작부터 가장 늦은 종료까지 병합한다.
- 변곡점의 영향 범위는 해당 변곡점부터 다음 변곡점까지다. 마지막 변곡점은 조회 종료일까지 표시한다. 시각적 묶음 처리 전에 개별 영향 범위를 계산한다.
- 실험은 노란 배경·검은 아이콘으로 구분한다. 호버 시 예측선을 관측선의 기준 지점에서 이어지는 점선으로 표시한다.
- 예측선의 우측 끝에 현재 표시 구간 마지막 값의 기준 대비 증감률을 표시한다.
- 새 실험은 `N` 배지를 표시한다. 어노테이션이 화면에 노출되거나 호버·클릭되면 읽음 처리한다. 화면 밖이거나 등록 창에 가려진 동안은 읽음 처리하지 않는다.
- 읽음 상태는 유지하고, 기존 실험에는 새 배지를 일괄 부여하지 않는다.

### 5.3 채널별 상세 분석

- 채널별 회선 비중 우측의 세로 `⋮` 메뉴에서 상세 분석으로 이동한다.
- 제목·조회 기간·기간 선택 헤더는 로딩 중에도 유지한다. 하단 콘텐츠만 스켈레톤으로 표시한다.
- 가입 기여, 신규 가입·번호이동 구성, 회선·해지·매출·순익과 채널 타임라인을 제공한다.
- 타임라인은 현황 화면과 같은 어노테이션 규칙을 사용한다. 실험은 해당 채널 또는 전체 채널 대상만 표시한다.
- 채널 상세 타임라인의 우측에는 중복 상세보기 메뉴를 제공하지 않는다.
- 별도 ‘채널 실험 제안’ 목록을 반복 배치하지 않는다. 정책 실험은 공통 등록 흐름을 이용한다.

### 5.4 상세 분석

| 분석 유형 | 주요 내용 |
| --- | --- |
| 기간 별 상세 분석 | 선택 기간의 실적 변화, 시장 이벤트, 정책 후보와 예상 효과 |
| 자사 이벤트 상세 분석 | 변경 요건·적용 기간·채널, 전후 실적, 후속 정책 검토 |
| 경쟁사·기타 이벤트 상세 분석 | 출처·변경 내용, 자사와의 차이, 영향 가설과 대응 검토 |
| 변곡점 상세 분석 | 변화 시점·다음 변곡점까지의 영향 범위, 근거 지표와 원인 가설 |
| 실험 상세 | 등록 요건·산출 기준·알고리즘·기간, 기준 전망과 실험 예측, 결과 평가 |

최초 페이지 진입용 로딩 화면부터 제목과 조회 조건을 표시한다. 분석 화면은 ‘분석 중’, 요건 조회 화면은 ‘상세 내용을 불러오는 중’과 콘텐츠 스켈레톤을 사용한다.

### 5.5 이벤트 등록

- 등록 유형 → 기본 정보 → 기간·출처 → 프롬프트 요건 분석 → 검토 → 등록의 위저드로 구성한다.
- 기본 정보는 유형·제목·수행 주체·선택적 적용 채널을 포함한다. 새 수행 주체와 채널을 추가할 수 있다.
- 적용 시작은 필수, 종료는 선택 사항이다. 출처 유형·출처명·URL·관측 시점을 기록한다.
- 템플릿을 선택하거나 프롬프트를 입력한다. 요약·정형 요건을 확인한 뒤 최종 등록한다.
- 분석·등록 중에는 진행 상태를 표시하고 중복 등록을 방지한다. 실패 시 입력 내용을 유지한다.

## 6. AI 자동 제안과 정책 실험

### 6.1 우선순위와 산출 기준

공통 중점 지표는 `설정 → AI 판단`에서 선택한다. 자동 제안에서는 이를 초기값으로 사용하되, 이번 실험의 우선순위를 별도로 지정한다. 실험별 선택으로 공통 설정을 덮어쓰지 않는다.

| 진입 위치 | 산출 기준 |
| --- | --- |
| 시장.정책 현황 | 현재 사업자·조회 기간·기간 내 참조 이벤트와 변곡점 |
| 기간 별 상세 분석 | 분석 중인 기간·사업자와 참조 데이터 |
| 채널 상세 분석 | 해당 채널의 실적·채널 적용 이벤트·시장 변화 |
| 이벤트 상세 분석 | 선택한 이벤트와 관련 기간·자사 실적 |
| 변곡점 상세 분석 | 선택 변곡점과 영향 구간·관련 이벤트 |

선택 이벤트·변곡점이 있으면 해당 선택을 우선한다. 없으면 조회 기간의 참조 대상에서 산출한다. 숨김·참조 제외 설정을 반영한다. 산출 기준은 제안 화면에 표시하고 실험과 함께 저장한다.

### 6.2 정책 요건과 후보

정책은 가격 변화율, 데이터·통화 혜택, 포인트, 무료 제공 항목, 적용 대상·채널, 비용, 기간으로 정형화한다. 수정은 구체적인 수치·항목 선택을 기본으로 한다. 신규 유형은 확장 가능하게 관리한다.

| 비교안 | 기본 적용 조건 | 비교 목적 |
| --- | --- | --- |
| 현행 유지 | 추가 정책 변경 없음 | 정책을 바꾸지 않는 기준 전망 |
| 단기 검증 | 동일 정책 7일 적용 | 초기 반응·비용 확인 |
| 장기 검증 | 동일 정책 28일 적용 | 효과 지속성·누적 비용 확인 |

기본 예측 기간은 세 안 모두 42일이다. 적용 기간과 예측 기간은 구분해 변경할 수 있으며, 미리보기와 저장 후 계산에 동일한 조건을 사용한다. 적용 종료 후에는 정책 효과를 제거하고 기준 전망으로 복귀한다.

과거 시점의 실험도 등록할 수 있다. 단, 전망의 기준 데이터는 실험 시작 이전 자료로 제한하고, 이후 관측값은 결과 비교에만 사용한다.

### 6.3 통합 예상 차트

- 등록·상세 화면은 같은 ‘실험 예상 차트’ 컴포넌트를 사용한다.
- 관측 실적·현행 유지 기준 전망·실험 적용 예측을 같은 기간과 축으로 비교한다.
- 회선·해지·매출·순익을 선택한다. 회선 민감도 조절은 제공하지 않는다.
- 이동평균·지수평활·감쇠 추세 지수평활·선형 추세 및 추가 모델 비교를 제공한다.
- 등록 시 선택한 알고리즘을 저장한다. 상세 화면의 임시 알고리즘 비교는 등록된 실험·집계값을 변경하지 않는다.
- 일자별 예측은 페이지당 최대 10건을 표시한다.
- 실험은 이벤트 연결 없이 등록할 수 있다. 채널은 선택 사항이며 미선택 시 전체 채널 대상이다.
- 실험 묶음은 이벤트 관리에서 그룹으로 관리한다. 효과를 무조건 합산하지 않는다.

| 시장 데이터 | 모요·경쟁사 공식 요금제·프로모션·공식 발표·뉴스, 출처 URL과 관측 시점 |
| 상품 비교 | 망·데이터·통화·QoS·할인 기간 기준의 유사 상품군, 할인 요금·종료 후 요금·총 납부액 구분 |
| 내부 실적 | 사업자·일시·채널별 회선·해지·매출·순익, 원천 집계 기준 |
| 이벤트 | 식별자·유형·주체·제목·시작/종료·채널·변경 전후·출처·등록 이력 |
| 변곡점 | 시작 시점·다음 변곡점·평가 방식·근거 지표·판단 이력 |
| 실험 | 정책 요건·우선순위·적용/예측 기간·알고리즘·비용 가정·채널·산출 근거·등록/읽음 상태 |
| 정책 제약 | 우선 목표, 최소 마진·예산·변경 한도·중단 조건을 현업과 합의 |
| 계산 분리 | 수치 계산은 코드, 예측은 통계·ML, 추출·요약·설명은 LLM 역할로 분리 |
| 판단 품질 | 사실·가설·예측 구분. 정보 부족과 수집 실패는 판단 보류. 관망에는 재검토 조건 제시 |
| LLMOps | 데이터·모델·프롬프트 버전, 근거, 제안, 수정·채택·기각 사유, 적용 결과 추적 |
| 보안·권한 | 운영 데이터 연동 전 인증·조직별 권한·조회 범위·감사 이력 정의 |

마케터 피드백은 문구 수정과 분석 기준 수정으로 구분한다. 반복 피드백은 평가 데이터로 관리하고, 모델·프롬프트 변경 전후의 품질을 비교한다.

## 8. 화면 품질 기준

- 공통 컴포넌트·타이포그래피·간격·라이트/다크 테마를 사용한다.
- 제목·업무 행동을 우선하고, 영문 장식 제목·반복 설명·홍보성 문구를 최소화한다.
- 데이터 상태와 산출 방법은 짧은 배지·툴팁으로 제공한다. 실제 보도와 합성 실적, 모델 예측과 가정 기반 시뮬레이션을 혼동시키지 않는다.
- 표·차트의 기간·단위·기준값을 일관되게 표시한다. 알림·선택·오류는 색상 외에 텍스트로도 구분한다.
- 헤더를 유지한 스켈레톤으로 화면 전환을 안내하고, 오래된 조건의 결과가 새 조건의 결과로 노출되지 않게 한다.

## 9. 실증 지표와 인수 기준

정량 목표치는 현업 요건 분석과 기존 업무 측정 후 확정한다.

| 평가 영역 | 지표 |
| --- | --- |
| 데이터 | 수집 성공률·최신성·중복률·정제 오류율·출처 추적 가능률 |
| 분석 | 변화 감지 정확도·요약 근거 정확도·현황 파악 시간 |
| 정책 제안 | 현업 적정성 평가·채택/수정/기각 비율·검토 시간 |
| 실험 | 예측 오차·구간별 편향·기준 전망 대비 개선·가정과 실제 조건 일치 여부 |
| 운영 | 오류율·응답 시간·등록 실패율·피드백 반영 소요시간 |

주요 인수 조건:

1. 조회 기간·사업자·채널 변경이 차트·요약·제안 근거에 일관되게 반영된다.
2. 상세 진입과 기간 변경 중 헤더가 유지되고 콘텐츠 스켈레톤이 표시된다.
3. 자동 제안의 우선순위는 중복되지 않으며, 변경 시 제안과 산출 근거가 갱신된다.
4. 선택한 이벤트·변곡점·기간·채널·우선순위를 등록 후에도 추적할 수 있다.
5. 현행 유지·단기·장기 안의 미리보기와 등록 후 예측 계산이 일치한다.
6. 적용 종료 후 정책 효과가 종료되고, 과거 실험의 예측 계산에 미래 관측값이 유입되지 않는다.
7. 채널 타임라인에 다른 채널 전용 실험이 표시되지 않는다.
8. 변곡점 영향 구간과 묶음 영역이 다음 변곡점 경계에 맞게 표시된다.
9. 새 실험의 N 배지는 실제 노출·확인 후 해제되며 재방문 시 유지된다.
10. 실제 정책은 사용자의 별도 업무 절차 없이 자동 변경되지 않는다.

## 10. 현재 구현과 운영 전환의 차이

현재 저장소는 화면·등록 흐름·정책 조건 비교를 검증할 수 있는 상태다. 상용 운영 완료와 동일하게 해석하지 않는다.

| 항목 | 현재 상태 | 운영 전환 요구 |
| --- | --- | --- |
| 데이터 | 출처가 있는 시장 이벤트와 가상 이벤트, 합성 실적을 함께 사용 | 실제 수집 파이프라인, 내부 실적·원가·정책 이력 연동 |
| 시간 해상도 | 일 단위 자료와 기간 집계 중심 | 시간대별 분석을 위한 원천 데이터 확보 |
| 자동 제안 | 기간·채널·이벤트·우선순위를 반영한 규칙 기반 구성 | 평가된 LLM 연동, 근거 검색, 정책 제약 검증 |
| 예측 | 통계 계산과 정책 가정 적용. Prophet·SARIMAX·XGBoost 선택은 근사 계산 | 해당 모델 학습·검증·서빙, 오차와 불확실성 평가 |
| 변곡점 | 사전 구성 지점 및 수동 이벤트 활용 | 실제 지표 기반 탐지·평가와 영향 구간 추적 |
| 저장·권한 | 브라우저 저장 중심 | 서버 저장, 사용자·조직 권한, 동시 편집·감사 로그 |
| 채팅 분석 | 제한된 질문·응답과 시뮬레이션 연결 | 근거 기반 질의·정책 수정·실험 비교의 대화형 처리 |
| 품질 관리 | 코드 검사·계산 검증 | 데이터·모델·프롬프트 운영 평가와 장애 대응 |

기존에 사후 구성된 예측 곡선은 실제 사전 예측 성능 평가에서 제외한다. 실제 효과 평가는 대조군·계절성·동시 캠페인 등을 고려한 별도 평가 설계를 사용한다.

## 11. 제외 범위와 미확정 사항

- 초기 범위에서 실제 통신 요금·혜택의 무승인 자동 반영은 제외한다.
- 경쟁사의 비공개 매출·순익을 실제 관측 데이터로 제공하지 않는다.
- 단순 상관관계를 정책의 인과효과로 확정하지 않는다.
- 운영 전 확정: 회선·해지·순익의 집계 정의, 데이터 이용·수집 권한, 동기화 주기, 사업자별 채널 체계, 정책 제약, 정량 성공 기준, 담당자와 운영 권한.
- 롤백: 화면·설정 변경 이력과 이전 버전을 보존한다. 운영 정책의 실제 롤백은 적용 시스템의 별도 승인·절차와 연결한다.
