# 시장 분석 데이터와 화면 연결

## 원천 및 사용처

| 데이터 | 원천 | 사용하는 화면 | 일관성 기준 |
| --- | --- | --- | --- |
| 일별 실적 | `buildPerformance` | 타임라인, 기간 탐색, 상세 분석, 데이터 조회, 예측 | 회선·해지·금액은 합산, 순익=매출−비용, 이익률은 합계 금액으로 재계산 |
| 채널 실적 | `buildChannelDaily` → `buildChannels` | 채널 목록·상세, 데이터 조회 | 일별 회선·매출 합계는 전체 실적과 일치, 회선=010 신규+번호이동 |
| 이벤트 | `useEventCatalog` | 타임라인, 알림, 이벤트 관리, 상세 근거, 심층분석 | ID 유일, 유효한 발생 일시, 종료≥시작, 한 건에 여러 유형 가능 |
| 참조 설정 | `useAnalysisPreferences` | 설정, 분석 대상 제외 | 워크스페이스별 저장, 비참조 소스·유형은 분석에서 제외 |
| 숨김 | `useEventVisibility` | 알림, 이벤트, 분석 제외 | 원본은 보존하며 분석 대상과 근거에서 제외 |
| 이벤트 요약 | `buildEventInsights` → `buildAnalysis` | 인사이트, 상세 분석, 심층분석 진입 요약 | 동일 기간·제외 목록·카탈로그·워크스페이스로 계산 |
| 예측 | `forecastPolicy` | 정책 비교, 채팅 차트 | 대안별 선택 유지, 추천에서 빠진 모델은 기본값으로 복귀, 회선·해지·매출 음수 방지 |

## 기간과 소유 구분

- 시작일과 종료일을 포함한다. 종료일 없는 이벤트는 당일 사건이며 무기한 진행으로 해석하지 않는다.
- 기간 이전에 시작한 진행 이벤트는 조회 기간과 겹치면 한 번 포함한다.
- 이벤트의 수행 주체와 현재 워크스페이스가 대소문자 무관하게 일치할 때 해당 워크스페이스의 이벤트다. 나머지는 경쟁사·기타이다.
- 월·연도 집계는 같은 일별 원천을 사용한다. 일별 임계값을 집계 합계에 적용하지 않는다.
- 숨김·참조 제외는 이벤트와 그 근거를 제외하는 동작이며, 이미 관측된 실적 수치를 삭제하거나 재작성하지 않는다.

## 현재 구현 경계

- 일별 실적은 아직 워크스페이스 공통의 결정적 시연 데이터다. 실제 사업별 성과 차이는 구현되어 있지 않으며, 운영 데이터 연결 시 `(workspace_id, date)`로 분리해야 한다.
- 시장 이벤트 카탈로그와 숨김 상태는 공통이다. 참조 설정은 워크스페이스별이다.
- 기본 이벤트의 출처 URL이 없는 경우 미등록으로 표시한다. 검증되지 않은 출처나 수행 사실을 생성해 채우지 않는다.
- AIR의 9월 회복 이야기는 AIR의 대응이다. 다른 워크스페이스의 자체 대응으로 분류하지 않는다.
- Prophet·SARIMAX·XGBoost 선택 결과는 UI 시연용 계산 어댑터다. 실제 학습 모델·서버 추론·백테스트는 미연동이다.
- 심층 채팅은 준비된 질문 분류와 조건부 계산이다. LLM 호출·프롬프트 캐싱·인과 추론 서버는 미연동이다.

## 재검증

`node scripts/check-market-data.cjs`

전체 기간·1개월·1주·1일에 대해 일/월/연 합계, 채널 정합성, 워크스페이스 소유 구분, 이벤트 제외, 중복/날짜 검증, 모든 예측 방식의 유효 숫자와 수량 제약을 검사한다.
