# Phase 2: 기본 분석에서 AI 심층 분석 이어하기

## 제공 방식

상세 분석의 'AI와 분석 이어하기'에서 전용 분석 공간을 연다. 왼쪽은 대화와 가정 입력, 오른쪽은 차트·비교표·근거 패널로 구성한다. 기존 플로팅 챗봇은 진입점으로 사용하고, 긴 시뮬레이션 결과는 전용 공간에서 보여준다. 현재 UI는 Phase 2 예정 안내이며 실제 AI 호출은 연결하지 않는다.

1. 기간, 워크스페이스, 중점 지표, 참조 소스/이벤트 유형, 제외 이벤트, 기준 분석 ID를 전달한다.
2. 질문 유형에 따라 요금 탄력도, 채널 예산 재배분, 변화 원인 검토를 선택한다.
3. AI는 필요한 데이터·가정·제약을 제시하고 부족한 입력은 질문한다.
4. 계산 도구를 실행해 결과 차트, 민감도 표, 비용/수익 비교, 근거 이벤트를 반환한다.
5. 사용자가 가정을 바꾸면 새 분석 분기로 저장한다. 이전 결과와 나란히 비교하고 정책 검토안으로 보관한다.

## 기본 분석 / 서버 캐시

기본 분석은 서버에서 버전 관리된 프롬프트와 정규화된 기간 데이터를 이용해 생성한다. 캐시 키는 workspace + 기간 + 중점 지표 + 소스/이벤트 유형 설정 버전 + 제외 이벤트 목록 해시 + 데이터 스냅샷 버전 + 프롬프트/모델 버전으로 만든다. 데이터나 설정이 바뀌면 기존 캐시를 재사용하지 않는다. 권한 범위가 다른 워크스페이스 간에는 공유하지 않는다.

기본 분석 응답에는 analysisId, generatedAt, dataSnapshotId, promptVersion, modelVersion, evidenceIds, 가정, 결과 구조를 저장한다. 심층 분석은 전문을 매번 새로 만드는 대신 해당 분석과 근거 데이터 스냅샷을 참조한다. 대화 분기에는 부모 analysisId, 변경된 가정, 도구 입력/출력, 실행 버전과 사용자가 선택한 대안을 기록한다.

## 계산과 추론의 구분

- P1: 이동평균, 단순 지수평활(α=0.3), 최소제곱 선형 추세를 실제 관측값에 적용한다. 대안 효과는 별도의 정책 가정이며 인과 효과로 표현하지 않는다.
- Phase 2: 요금·혜택·예산·원가·고객군·유입·전환·유지 이력으로 탄력도와 채널 반응을 추정한다. 데이터가 부족하면 추정값 대신 사용자 가정 범위를 사용한다.
- LLM은 질문 해석, 근거 요약, 가설 비교를 맡는다. 수치 계산은 검증된 도구가 담당하고, 응답은 해당 도구 결과를 참조한다.
- 복잡한 시뮬레이션은 작업 ID 기반 비동기 실행, 진행 상태, 취소·재시도와 재현 가능한 seed를 제공한다.
- 결과는 기준 전망, 정책 적용 전망, 불확실성 구간을 구분한다. 반사실적 대안 비교는 인과 추정의 한계를 명시하고, 시계열 백테스트와 민감도 검사를 함께 제공한다.

## 우선 제공할 결과 형태

| 질문 | 입력 | 출력 |
| --- | --- | --- |
| 일부 요금제 5% 인하 | 상품·변경 폭·기간·원가·고객군 | 가입/해지/순익 곡선, 손익분기점, 탄력도 범위 |
| TOSS/MOYO 예산 재배분 | 총예산·채널별 제약·혜택·목표 지표 | 대안별 비교표, 비용 대비 성과, 민감도 |
| 회복 원인 검토 | 이벤트·채널 노출·가격·비교군 | 근거 연결, 대안 가설, 추가 데이터 요청 |

## 구현 경계

이 문서는 Phase 2 설계 제안이다. 현재 서버 캐시, AI 추론, 탄력도 추정, 비동기 시뮬레이션은 구현되지 않았다. P1 차트 예측 계산과 Phase 2 안내 UI만 제공한다.
