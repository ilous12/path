# MARS 서비스 설계 — 수집·추론·표시 정보 단위

작성일: 2026-09-28  
상태: 요구사항 정의 초안. 아래는 목표 설계이며 현재 구현 여부를 의미하지 않는다.

## 1. 목적과 서비스 흐름

마케터가 시장과 사업 실적을 이해하고, 판매 정책·캠페인을 등록한 뒤 예상 효과를 검토·조정하여 실행하고, 실제 결과까지 비교하도록 지원한다.

- **입력(소스):** 수집 대상 선별 → 수집 방안 식별 → 원문 수집·보존 → 경량 모델로 추출·정규화 → 규칙 검증 → DB 저장
- **출력(추론):** 기간·워크스페이스·중점 지표 선택 → 데이터 조회·계산 → 일반/복합 추론 → 근거 검증 → 구조화된 결과로 화면 표시
- **실행과 환류:** 캠페인 등록 → 결과 예측 → 조건 조정·재예측 → 담당자 확정 → 실행 → 실제 성과 수집 → 예측 대비 평가

수치 집계·증감률 계산은 계산 계층에서 수행한다. 모델은 비정형 자료의 의미 추출, 변화 해석, 가설 및 대안 생성에 사용한다. 예측 수치는 예측 모델의 결과를 받아 설명하며, LLM이 임의로 채우지 않는다.

## 2. 워크스페이스와 분석 범위

| 영역 | 주요 목적 | 기본 분석 단위 | 주요 표시 정보 |
|---|---|---|---|
| Home / Online | aiir·TDDS 온라인 사업 통합 관리 | 기간 × Online, 하위 aiir·TDDS | 통합 실적·목표·전망, TDDS/aiir별 요약·기여도·캠페인 영향 |
| aiir | 온라인 성장과 판매 경쟁력 관리 | 기간 × aiir × 상품 × 채널 | 월간 순증 목표, 가입·해지·순증·매출·순익, 요금제 경쟁력 |
| TDDS | 온라인 성장과 판매 경쟁력 관리 | 기간 × TDDS × 상품 × 채널 | 월간 순증 목표, 가입·해지·순증·매출·순익, 요금제 경쟁력 |
| MVVNO | 시장·사업자·포트폴리오와 재원 효율 관리 | 기간 × 망 × 사업자 × 상품군 | 신규·번호이동·순증·매출·점유율, 목표·손익·지원 재원 효과 |

Home 통합은 지표 정의·기간·범위가 동일한 aiir·TDDS 실적만 합산한다. 비율은 분자·분모를 합쳐 재계산하며 사업부 비율을 단순 평균하지 않는다. 사업부 간 이동 및 중복 집계 처리 기준은 마케터와 확정한다.

## 3. 수집 대상과 수집 방안

아래 소스는 수집 후보이며 접근 권한·제공 형식·실제 확보 가능 여부를 확인하여 확정한다.

| 수집 대상 | 후보 소스 | 수집 방안 | 보존할 원문 단위 | 정규화 결과 |
|---|---|---|---|---|
| 사업 실적 | 내부 실적 DB, 데이터마트, 운영 시스템 | 읽기 전용 DB/API, 파일 업로드 | 원천 행 또는 기간별 집계 파일 | 실적 관측값 |
| 전체 요금제 | MNO·MVVNO 사업자 공식 사이트 | API/피드 우선, 제공되지 않으면 웹 수집 | 요금제 페이지의 시점별 사본 | 상품·상품 버전 |
| 채널별 판매 조건 | 자사 APP/WEB, MOYO 등 중간 사업자, TOSS·KAKAOPAY 등 플랫폼 | API, 웹 수집, 제휴 파일 | 상품 상세·혜택·유의사항의 시점별 사본 | 판매 조건 버전 |
| 판매 정책 변경 | 내부 정책 문서, 사업자·채널 공지 | 문서 업로드, API, 웹 수집 | 문서·공지 및 첨부 자료 | 정책·변경 이벤트 |
| 캠페인 | 내부 캠페인 등록 및 운영 시스템 | 입력 폼, API, 파일 | 등록안·확정안·실행 결과 | 캠페인·버전·실행 이력 |
| 시장 변화 | 공식 시장 통계, 사업자 공지, 뉴스·커뮤니티 | 공개 데이터/API, 웹 수집 | 통계 표·게시물·문서 | 시장 관측값·이벤트 |
| 목표·손익 | 사업 계획, 재무·정산 자료 | DB/API, 파일, 수동 입력 | 승인된 목표·원가·정산 버전 | 목표·원가·손익 기준 |
| 현장 정보 | 마케터 수동 등록 | 입력 폼·증빙 첨부 | 입력 내용과 첨부 원본 | 수동 이벤트·보완 정보 |

### 3.1 소스 등록 시 필요한 정보

- **소스 식별:** 소스명, URL/시스템/파일 위치, 소유 사업자, 채널, 적용 워크스페이스
- **수집 범위:** 상품·기간·이벤트 유형, 포함/제외 범위, 참조 여부
- **수집 방식:** API / DB / 웹 / 파일 / 수동, 인증·접근 조건, 담당자
- **추출 방식:** AI 분석, 이벤트 유형 자동 선택 기본 및 수동 지정
- **품질 기준:** 공식/비공식 여부, 신뢰 등급, 필수 항목, 확인 담당자
- **이력:** 등록·수정 수행자와 일시, 최근 수집 결과, 오류·누락 상태

수집/감지 주기 선택은 사용자 설정 화면에 제공하지 않는다. 수집 일시와 데이터 기준 시점은 별도로 기록한다.

### 3.2 수집 → 경량 모델 → DB 처리 단위

| 단계 | 처리 내용 | 결과 단위 |
|---|---|---|
| 원문 보존 | URL·문서·파일·행 식별자, 수집 시각, 콘텐츠 해시 보존 | 원문 스냅샷 1건 |
| 경량 모델 추출 | 사업자·상품·가격·혜택·기간·변경 내용 추출, 근거 위치 연결 | 구조화된 추출 레코드 1건 |
| 정규화 | 명칭을 기준 ID에 연결, 날짜·통화·용량·세금 기준 통일 | 표준 레코드 1건 |
| 검증 | 필수값·타입·기간·금액 검증, 중복·기존 버전 비교 | 승인 / 검토 대기 / 실패 |
| 적재 | 검증 통과 레코드 저장, 원문·추출 모델·규칙 버전 연결 | DB 레코드·버전 1건 |
| 변화 감지 | 동일 대상의 전후 버전 비교, 의미 있는 변경 이벤트 생성 | 이벤트 1건과 근거 연결 |

필수값이 없거나 매칭이 불확실한 결과는 검토 대기로 남긴다. 누락값을 0으로 바꾸거나, 수집하지 않은 날짜·가격·혜택을 생성하지 않는다. 수집 재시도는 소스 키·원문 해시·버전 기준으로 중복 삽입을 방지한다.

### 4.1 요금제와 판매 조건의 구분

하나의 기본 요금제가 여러 채널·기간·혜택으로 판매될 수 있다. 이를 서로 다른 기본 상품으로 중복 등록하지 않고, 상품에 연결된 판매 조건으로 구분한다.

- 상품 비교: 데이터·통화·속도·망 등 유사 사양끼리 비교
- 판매 조건 비교: 동일/유사 상품의 채널·가입 유형·판매 기간·혜택 차이 비교
- 실질 부담액 비교: 동일 이용 기간을 기준으로 할인 종료 후 요금·의무 비용을 포함
- 현금성/비현금성 혜택 분리: 조건부 포인트나 데이터 혜택을 근거 없이 현금으로 환산하지 않음

### 4.2 모든 정보에 필요한 공통 메타데이터

- **출처:** source_id, 원문 URL/파일/행, 증빙 위치, 원문 해시
- **수행 주체:** 변경·정책의 사업 주체, 수집/입력 수행자, 확인/승인 담당자를 구분
- **시점:** 사건 발생, 조건 적용 시작·종료, 출처 게시, 수집, 저장·수정, 실적 기준 기간을 구분
- **처리 계보:** 원문 → 추출 결과 → 정규화 레코드 → 분석 입력 → 표시 결과의 ID 연결
- **품질:** 확정/잠정/미확인, 누락 사유, 추출 신뢰도, 검토 상태
- **이력:** 버전, 이전 버전, 변경 사유, 숨김·참조 제외 여부

숨기기는 원문이나 실적을 삭제하지 않는다. 이벤트의 분석 참조 제외로 처리하고, 관련 Insight·이벤트 기반 예측은 재평가한다. 관측된 실제 실적은 그대로 유지한다.

## 5. 지표와 측정 단위

| 지표 | 단위·집계 성격 | 마케터가 확정할 정의 |
|---|---|---|
| 가입 | 기간 내 회선 수, 흐름 | 개통 완료 기준, 취소·철회 처리, 010 신규/MNP 구분 |
| 해지 | 기간 내 회선 수, 흐름 | 해지 완료 기준, 번호이동 해지·직권 해지 포함 범위 |
| 순증 | 기간 내 회선 수, 흐름 | 가입−해지 및 정정·이관 처리 기준 |
| 보유 회선 | 특정 시점의 회선 수, 잔량 | 정상/정지 포함 범위, 일말·월말 기준; 기간 합산 금지 |
| 해지율 | %, 비율 | 기간과 분모(기초/평균 보유 회선 등)를 명시 |
| 매출 | ₩, 기간 금액 | 청구/인식/수납 기준, 부가세·환불·정산 기준 |
| 비용·순익 | ₩, 기간 금액 | 포함 원가·지원금·마케팅비·배부 비용, 순익 정의 |
| 이익률 | %, 비율 | 분자 손익 종류와 매출 분모 |
| 점유율·채널 비중 | %, 비율 | 가입/보유/매출 등 기준 지표와 전체 모집단 |

## 8. 프롬프트·스킬의 입출력 계약

여기서 스킬은 특정 업무를 반복 수행하기 위한 데이터 조회·계산·모델 호출·검증 절차 묶음이다.

### 입력

- workspace, 분석 시작/종료, 중점 지표(회선 성장/이탈 방어/수익성)
- 대상 사업자·상품·채널 및 필터, 참조 제외 이벤트
- 데이터 스냅샷 ID, 계산된 지표·비교 기준, 근거 레코드 ID
- 판단 기준 버전, 프롬프트/스킬 버전
- 캠페인 분석 시 계획 버전, 예측 실행 ID, 예측 구간과 가정

### 출력

- 제목·핵심 요약
- 발생 / 영향 / 대응 / 경과: 내용, 수치, 근거 ID; 해당 근거가 없으면 N/A
- 관측 사실 / 원인 가설 / 예측 결과 / 제안의 구분
- 판단: 대응 필요 / 관망 / 대응 불필요 / 판단 보류
- 대안·기대 효과·비용·위험·추가 확인 정보
- 차트용 데이터 참조, 표시 단위, 비교 기준
- 데이터 기준 시점, 생성 시각, 불확실성·누락·검증 상태

### 실행·갱신 규칙

- 일반 분석과 복합 분석의 템플릿을 분리하고 각각 버전 관리한다.
- 캐시 키에 워크스페이스·기간·필터·중점 지표·데이터 버전·판단 기준·프롬프트/스킬 버전을 포함한다.
- 캠페인 조건이나 알고리즘이 달라지면 별도 예측 실행으로 저장한다.
- 갱신 중 스켈레톤/분석 상태를 표시하고 완료된 결과를 교체한다. 실패 시 기존 결과의 기준 시점과 실패 상태를 함께 표시한다.
- 출력 수치가 계산 결과와 일치하는지, 근거 ID가 유효한지 검증한 뒤 표시한다.

## 10. 캠페인 등록·예측·실행 연결

1. **등록:** 판매 정책 변경과 캠페인 대상을 연결한다.
2. **예측:** 같은 기준 시점에서 미시행 전망과 적용 전망을 계산한다. 선택 가능한 알고리즘은 대상·데이터 적합도에 따라 최대 3개로 제공한다.
3. **조정:** 예측 결과를 보고 조건·예산·기간을 수정하면 새 계획 버전과 예측을 생성한다.
4. **확정:** 담당자가 선택한 계획 버전·예측·예산을 함께 고정한다.
5. **실행:** 실행 시스템 연계 또는 담당자 실행 확인으로 실제 시작 여부를 기록한다. 등록·예측 완료만으로 실행 처리하지 않는다.
6. **분석:** 확정 당시 예측은 보존하고 실제 실적 및 최신 전망과 구분하여 비교한다.

캠페인 대상이 겹치면 혜택 중복 적용과 실적 귀속 기준을 정의한다. 여러 캠페인의 예상 효과를 단순 합산하지 않는다. 단순 전후 증감은 관측 결과이며, 캠페인의 인과 효과로 표현하려면 비교군·평가 방법과 가정을 함께 제시한다.

## 12. 완료 판정 기준

- 표시된 모든 사실·수치는 원천 레코드와 출처까지 추적할 수 있다.
